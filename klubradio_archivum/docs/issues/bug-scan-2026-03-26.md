## CRITICAL (7 bugs)

### C1: ProfileProvider `_profile!` crashes before load()

- **File:** `lib/providers/profile_provider.dart` — lines 14, 29, 35, 41, 65
- **Category:** Null Dereference
- **Description:** All mutation methods (`setLanguage`, `setPlaybackSpeed`, `setMaxAutoDownload`, `toggleFavouriteEpisode`, `setSubscriptions`, `addRecentlyPlayed`) access the `profile` getter which uses `_profile!`. The provider initializes with `_profile = null`. If any mutation method is called before `load()` completes, the app crashes with "Null check operator used on a null value".
- **Impact:** App crash on any profile mutation before initialization.

### C2: "Recommended Shows" section is fake — remove it

- **File:** `lib/screens/discover_screen/discover_screen.dart` — line 111
- **Category:** Data Flow Bug / Dead Code
- **Description:** The "Recommended Shows" section passes `latest.items` instead of data from the `rec` (RecommendedProvider). However, both `rec` and `latest` providers run the **same query** — there is no API endpoint or logic for actual recommendations. The `RecommendedProvider` should be removed entirely. The discover screen should only show: **Top Shows** (by play count), **Latest**, and **Search**. There is no data source for "Recommended".
- **Impact:** Misleading UI section that duplicates latest data. Dead provider code.
- **Fix:** Remove `RecommendedProvider`, remove "Recommended Shows" section from discover_screen, rename/reorganize remaining sections.

### C3: `toggleSubscription` parameter semantics are inverted

- **File:** `lib/screens/widgets/unsubscribe_dialog.dart` — line 42
- **Category:** Logic Bug
- **Description:** Calls `toggleSubscription(podcastId, true)` when unsubscribing. This works by accident due to double negation (`active: !isSubscribed` → `!true` = `false`), but the semantics are backwards and fragile.
- **Impact:** Works now but will break if toggle logic changes. Code maintainability risk.
- **Note:** `toggleSubscription` will be used everywhere — the parameter semantics need to be cleaned up once so all call sites are consistent.

### C4: Inverted success messages after subscribe/unsubscribe

- **File:** `lib/screens/podcast_detail_screen/podcast_detail_screen.dart` — lines 80–82
- **Category:** Logic Bug
- **Description:** After subscribing, shows "Unsubscribed successfully!" message. After unsubscribing, shows "Subscribed successfully!". The message logic uses `!isSubscribed` which inverts the actual outcome.
- **Impact:** Confusing/wrong user-facing feedback.
- **Note:** This feedback (SnackBar) is currently not visible on Linux/Windows. Low priority until platform feedback is fixed or verified on mobile.

### C5: Episode FK constraint without subscription check

- **File:** `lib/db/app_database.dart` — lines 63–65; `lib/providers/episode_provider.dart` — lines 93–116
- **Category:** Data Integrity / FK Violation
- **Description:** The Episodes table has a FOREIGN KEY on `podcast_id` referencing `subscriptions(podcast_id)`. However, `loadEpisodesIntoDb()` upserts episodes without ensuring the referenced subscription exists first.
- **Impact:** DB insertion fails for unsubscribed podcasts (if FK enforcement is enabled). Currently masked because Drift/SQLite doesn't enforce FKs by default.

### C6: `_processQueue()` race condition — maxParallel not enforced

- **File:** `lib/services/download_service.dart` — lines 168, 180, 290, 295
- **Category:** Concurrency / Race Condition
- **Description:** `_processQueue()` is called multiple times without awaiting. `_startDownload()` inside the loop is also not awaited. Multiple concurrent executions can dequeue the same episode or exceed `maxParallel` because `_activeDownloadCount` is checked before async operations complete.
- **Impact:** Download queue corruption; maxParallel limit bypassed; duplicate downloads possible.

### C7: Async void `_refresh()` method swallows exceptions

- **File:** `lib/repositories/podcast_repository.dart` — line 90
- **Category:** Logic Bug / Error Handling
- **Description:** The SWR background refresh method is declared `void` but is `async`. This is a Dart anti-pattern — any exception thrown inside is silently lost. The try-catch also silently swallows errors (`catch (_) {}`).
- **Impact:** Background cache refresh failures are completely invisible. Impossible to debug why data is stale.

## HIGH (15 bugs)

### H1: `s1.difference(s1)` always returns 0

- **File:** `lib/providers/podcast_provider.dart` — line 305
- **Category:** Logic Bug (copy-paste error)
- **Description:** Error logging for `loadTopShows()` calculates `s1.difference(s1)` instead of `s1.difference(s0)`. Always shows 0ms.
- **Impact:** Performance diagnostics broken for failed topShows loads.

### H2: Missing await on `_saveThemeMode()`

- **File:** `lib/providers/theme_provider.dart` — lines 57, 63
- **Category:** Concurrency / Missing Await
- **Description:** `toggleTheme()` and `setThemeMode()` call `_saveThemeMode()` without awaiting. `notifyListeners()` fires before SharedPreferences save completes.
- **Impact:** Theme preference lost if app is force-closed immediately after change.

### H3: `onEpisodeDownloaded()` not awaited

- **File:** `lib/services/download_service.dart` — line 339
- **Category:** Concurrency / Missing Await
- **Description:** In `_onUpdate()` completion handler, `episodeProvider.onEpisodeDownloaded()` is called without await. The audio source switch to local file races with `_activeDownloadCount--` and `_processQueue()`.
- **Impact:** Currently-playing episode may not switch to local playback source; download queue advances before completion is fully processed.

### H4: Missing `notifyListeners()` for non-playing episodes

- **File:** `lib/providers/episode_provider.dart` — line 156
- **Category:** State Management Bug
- **Description:** `onEpisodeDownloaded()` only calls `notifyListeners()` if the downloaded episode is the one currently playing. Background download completions don't notify UI listeners.
- **Impact:** Download progress indicators may not update for background downloads.

### H5: `addRecentlyPlayed()` not awaited

- **Files:** `lib/screens/home_screen/recently_played_list.dart` — line 48; `lib/screens/widgets/stateful/episode_list.dart` — line 53
- **Category:** Concurrency / Missing Await
- **Description:** Both call `podcastProvider.addRecentlyPlayed(ep)` without await inside async callbacks. Database write may not complete before widget disposes.
- **Impact:** Recently played data may not be saved; race condition with UI state.

### H6: Infinite spinner if `loadSubscription` fails

- **File:** `lib/screens/podcast_detail_screen/podcast_detail_screen.dart` — lines 45–54
- **Category:** UI Bug
- **Description:** Loading spinner displays while `!subscriptionProvider.loaded`. If `loadSubscription()` throws an unhandled exception, `_loaded` is never set to `true` (no try-finally).
- **Impact:** Permanent spinner; no error message shown to user.

### H7: Missing `!context.mounted` check after dialog

- **File:** `lib/screens/widgets/unsubscribe_dialog.dart` — lines 38–44
- **Category:** State Management / Memory Safety
- **Description:** After awaiting user input from the dialog (which can take arbitrary time), the code accesses providers via `context` without checking if the widget is still mounted.
- **Impact:** "Looking up a deactivated widget's ancestor" error if user navigated away.

### H8: Stream error type mismatch in AudioPlayerService

- **File:** `lib/services/audio_player_service.dart` — lines 76, 81, 86
- **Category:** Type Mismatch
- **Description:** `_bufferingController` is `StreamController<bool>` but `addError()` is called on it to emit exceptions. Listeners expecting `bool` values receive unexpected errors.
- **Impact:** Stream listeners may break or miss error events; error information lost.

### H9: Silent download error suppression

- **File:** `lib/services/download_service.dart` — line 134
- **Category:** Error Handling
- **Description:** The download stream subscription has `onError: (_) {}` which silently swallows all errors from the background_downloader update stream.
- **Impact:** Download failures completely invisible; no logging, no recovery, no user notification.

### H10: Unbounded search results

- **File:** `lib/services/api_service.dart` — lines 254–313
- **Category:** Performance / Memory
- **Description:** Both `searchPodcasts()` and `searchEpisodes()` make API queries with no LIMIT parameter. Common search terms could return thousands of results.
- **Impact:** Memory pressure, UI lag, potential crash on large result sets.

### H11: Recent search added even on API failure

- **File:** `lib/providers/podcast_provider.dart` — lines 230–231
- **Category:** State Management Bug
- **Description:** `addRecentSearch(query)` is called unconditionally before the try block. Failed queries still appear in recent searches.
- **Impact:** Recent search history polluted with terms that returned errors.

### H12: Invalid null-check pattern in RetentionDao

- **File:** `lib/db/daos.dart` — line 399
- **Category:** Null Safety
- **Description:** Pattern `s?.deleteAfterHours != null && s!.deleteAfterHours! > 0` — if `s` is null, the first condition is `false` and short-circuits, so this is technically safe. However, if the condition were accidentally reordered, it would NPE. The `s!` assertion after `s?.` is a code smell.
- **Impact:** Fragile code; maintainability risk.

### H13: Race condition in `ensureDefaults()`

- **File:** `lib/db/daos.dart` — lines 317–333
- **Category:** Concurrency
- **Description:** The check-then-insert pattern is not atomic. If called concurrently from multiple paths, both calls can see "no row exists" and both try to insert, causing a PRIMARY KEY constraint violation.
- **Impact:** App initialization may fail on concurrent startup paths.

### H14: Duplicate initialization in discover_screen

- **File:** `lib/screens/discover_screen/discover_screen.dart` — lines 25–70
- **Category:** Performance / State Management
- **Description:** Both `initState()` and `didChangeDependencies()` contain nearly identical code: cache loads + refresh calls for both `latest` and `rec` providers. This causes quadruple API calls on screen open.
- **Impact:** Unnecessary network requests, wasted bandwidth, UI flicker from multiple rebuilds.

### H15: Wrong loading state check in discover_screen

- **File:** `lib/screens/discover_screen/discover_screen.dart` — lines 97–111
- **Category:** UI Bug
- **Description:** Loading spinners check `latest.loading` but display data from `PodcastProvider.topShows`. These are independent providers with independent loading states.
- **Impact:** Spinner may show when data is ready, or data may be empty while spinner is hidden.
